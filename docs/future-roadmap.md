# 今後の改善ロードマップ

## 現在の基準

2026-08-12時点の最良構成は、`openutau-classic-worldline-faithful`へframe TCN v8の輪郭をpitch-onlyで適用する方式である。固定12文ではv8が輪郭なしに10対0（同程度2）、OpenJTalk実音声F0の直接適用に6対0（同程度6）だった。

この結果を回帰基準として固定する。新しいrendererやモデルは、同じ12文で非同率回答に負けず、歯抜け、高速の震え、ケロケロ・ガラガラ感、筒鳴りを再発させない場合だけ採用する。

## 優先順位

### P0: 最良構成を再現可能にする

1. v8モデル、特徴定義、学習metadata、使用したworldline native libraryとbridgeのhashをrelease artifactへ固定する。
2. GUI・CLI・serverで同じ音声設定を一つのprofileとして選べるようにする。
3. 必要ファイルがない場合は黙って別方式へ落とさず、標準`waveform`へ戻る理由を表示する。

### P0: 任意文章のアクセント特徴

現在のv8はOpenJTalkから事前exportしたモーラ単位特徴を必要とし、評価コーパス外の任意文章へそのまま適用できない。これがGUI統合の最大の阻害要因である。

1. OpenJTalk相当のアクセント句、核、単語境界、品詞を実行時に生成する。
2. Pythonやローカル環境へ暗黙依存せず、同梱可能な実装または明示的な補助プロセスにする。
3. 読みと特徴のモーラ整列率を記録し、不一致時はfail-fastまたは安全な輪郭なしへ戻す。
4. 全語を平板型へ落とすfallbackは既定で禁止する。

### P1: 未知文での汎化評価

学習・調整に使っていない文章を、アクセント核、複数アクセント句、疑問、固有名詞、数字、長文、促音・撥音・長音ごとに分けて評価する。固定12文は回帰試験として残し、未知文は汎化判定に使う。

疑問文は現在の学習コーパスにほぼ存在しないため、疑問終端だけをモデル容量で解決しようとしない。疑問を含む音声データを追加するか、文末riseを独立した制御層として扱う。

### P1: 学習データ拡張

v8の良さを保ったまま、OpenJTalk特徴とのexact alignmentが取れた人間音声を増やす。全量化の前後でdynamic range、アクセント核前後の高低差、句内下降、予測曲率を監査し、単なる中央値輪郭への縮退を防ぐ。

教師F0は有声島内で補間してmacro成分へ平滑化し、hard clipによるplateauを作らない。学習・評価・Go推論でmask、中心化、frame時刻を同一定義にする。

### P2: rendererの製品化

採用済みのOpenUtau timing、required duration、5点envelope、正規化相関収束を変更せずにfixture化する。OpenUtau式Q=5位相収束は聴感で0対3だったため採用しない。raw/WORLDの母音単位gating、周波数分割、全文一括WORLDも既定経路へ戻さない。

bridgeの欠落、native libraryのABI不一致、非44.1kHz音源を起動時に診断し、GUIへ具体的に表示する。

## GUI方針

GUIには次の二層を用意する。

- 通常利用: 原音重視の標準`waveform`と、必要資産が揃った時だけ使える自然イントネーションprofile。
- 研究利用: renderer、モデル、強度、診断情報を明示して選ぶ詳細設定。

未完成のv8任意文章対応を「自然イントネーション」として先に公開しない。当面はrendererの意味、採用状態、必要コンポーネントを画面内に表示し、棄却済みbackendを推奨候補に見せない。

## 完了条件

任意の日本語文をGUIへ入力し、追加の手作業なしで最良profileを生成できること。固定12文と未知文の双方で、標準waveformより聞き取りやすく、歯抜け・震え・加工感が許容範囲であること。失敗時には標準waveformへ安全に戻り、その理由が利用者に分かること。
