# 系列イントネーションモデル

従来の韻律モデルv3は、各モーラを独立に扱う線形回帰だった。v4は文全体の並びを入力する小型TCN（Temporal Convolutional Network）で、前後7モーラ程度の文脈から各モーラの相対F0を予測する。

学習損失には相対F0の誤差に加えて、隣接モーラ間のF0差分の誤差を含める。推論後に任意の平滑化規則を足すのではなく、どこで上げ下げするかと、その遷移量を同時に学習させるためである。モデルはPyTorchで学習するが、重みをJSONへ書き出し、合成時はGoだけで推論できる。

```powershell
python tools/train-intonation-tcn.py `
  --dataset out/prosody/jsut-5000.jsonl `
  --out out/prosody/jsut-5000-tcn-v4.json `
  --epochs 24 `
  --hidden 24 `
  --seed 7
```

JSUT 4,915文の決定的な9:1分割では、v3のpitch MAE 300.8 centsに対してv4は281.6 centsだった。F0抽出値には無声区間やオクターブ推定誤りが含まれるため絶対値は大きいが、同じ487文の検証集合で比較できる。

現時点の制約は次のとおり。

- 出力はモーラごとに1点であり、モーラ内の細かなF0変化はまだ学習しない。
- JSUT学習集合には疑問符を含む文がないため、疑問調を学習できない。
- 入力はモーラ、母音、文中位置、休符だけで、アクセント核や品詞・文節境界は含まない。

次の判断はv3対v4のブラインド聴感比較で行う。v4が改善するなら、次はF0ターゲットをモーラ内3点へ増やす。改善しない場合はモデル容量ではなく、アクセント情報を持たない入力表現と粗いアラインメントを先に直す。

実際のv3対v4比較はv4 3、v3 2、同程度7で、両方とも不自然という評価だった。このためモデル容量の拡大は停止した。次の診断ではOpen JTalkの語彙アクセント、アクセント句境界、核位置から評価コーパス用の輪郭を生成し、現行balancedと比較する。ここで改善すれば、次の学習モデルにはOpen JTalk由来の言語特徴を入力する。改善しなければF0モデルをいったん保留し、継続時間と接続へ戻る。

診断輪郭は次のように生成する。Open JTalkは実験時だけ `.tmp-openjtalk` に隔離しており、通常のGo合成には依存しない。

```powershell
$env:PYTHONPATH=(Resolve-Path .tmp-openjtalk).Path
python tools/openjtalk-accent-contours.py `
  --corpus docs/evaluation-corpus.json `
  --out out/prosody/openjtalk-accent-core-v1.json
```

診断比較はOpen JTalkアクセント4、現行2、同程度6で、モーラ位置だけから作った抑揚より「トモダチコレクション感」が減った。このため、Open JTalkとモーラ数・休止位置が一致したJSUT 4,612文を使い、次の特徴を追加したv5 TCNを学習した。

- アクセント句内の位置と残り長
- アクセント核の位置、および核の前・核・核の後
- アクセント句と単語の開始・終了
- 品詞と品詞細分類

モデルの隠れ層はv4と同じ24、3層のままである。v5の検証pitch MAEは277.3 centsだった。次の聴感試験では、Open JTalkから直接作った規則輪郭と、同じアクセント情報を入力してJSUTのF0を学習したv5輪郭を比較する。

比較結果は規則輪郭4、v5学習3、同程度5で、全体として「割といい」という評価だった。v5は二句を含む長文などで改善余地を示したが、規則輪郭を安定して上回らなかった。したがって規則輪郭を暫定基準とし、次の学習改善ではモデル容量ではなく、F0教師値とモーラ境界の品質を優先する。

## HTS音素時間ラベルによる再学習

`sarulab-speech/jsut-label` のBASIC5000ラベルを利用できる場合、`prosody-dataset` の `--labels` へ `labels/basic5000` を指定できる。ラベルは手動の音韻・韻律注釈とJuliusによる音素時刻推定に基づく。ラベル自体はCC BY-SA 4.0なので、派生データを配布する場合は原著者表示と継承条件を確認する。

```powershell
go run ./cmd/prosody-dataset `
  --jsut data/jsut/basic5000 `
  --labels .tmp-jsut-label/labels/basic5000 `
  --out out/prosody/jsut-5000-hts.jsonl `
  --workers 8
```

モーラ数と休止位置が一致した3,815文を採用した。従来データとの共通127,556モーラでは、境界時刻が中央値49.2ms、F0教師値が中央値128.8 cents変化し、有効F0率は72.1%から89.6%へ上がった。同じv5構造を再学習した検証pitch MAEは265.5 centsだった。

しかし聴感比較は推定境界v5 3、HTS境界v5 0、同程度9だった。調査すると評価コーパスの出力169モーラ中、旧v5は144、HTS版は155モーラが±3%の推論上限へ張り付いていた。学習時の広いF0教師と推論時clipが不整合だったため、次のv6では発話内で中心化した教師を学習時から出力範囲へ圧縮する。

v6は旧推定境界データを使い、中心化後の教師を学習時から0.97〜1.03へ制限した。評価コーパスの上下限張り付きは144/169から48/169へ減り、輪郭の標準偏差は49.3から36.8 centsになった。Open JTalk規則輪郭の35.8 centsに近い振幅で、規則輪郭をなぞるだけではない連続差を残している。

v5対v6の聴感比較はv5 1、v6 1、同程度10で、人間にはほぼ差がなかった。この後、複数音源で学習ピッチを直接レンダリングすると、音源によらずケロケロ感、クリック、WORLD経路の子音脱落が生じることを確認した。現在はモデル容量の拡大と直接ピッチ加工を停止し、PitchFactorなしの`waveform`を明瞭度基準にしている。次の研究では、予測F0を波形加工量ではなく、収録時F0が自然に合う原音を選ぶtarget costとして使う。
